IBKR Portfolio Manager

A cleaner, more intuitive portfolio dashboard for Interactive Brokers, with AI generated stock summaries. Personal learning project and portfolio piece, built to look professional on GitHub.

Stack
Broker: IB Gateway running locally, paper trading account, port 4002
Backend: Python 3.11, FastAPI, uvicorn, ib_async (the maintained fork of ib_insync; do not use ib_insync), yfinance for data IB doesn't provide
Frontend: React with Vite, in frontend/
AI summaries: Claude API, model set by AI_MODEL in .env (default claude-haiku-4-5, the single place to change it), key in .env as ANTHROPIC_API_KEY (backend only, never sent to the frontend)
Project layout
backend/         FastAPI app (main.py), config.py (loads .env, DATA_DIR), app_main.py + portfolio-backend.spec (PyInstaller entry for the Mac app), ibkr_hello.py, requirements.txt, venv/
frontend/        React app (Vite); frontend/src-tauri/ is the Mac app shell (Tauri 2, Rust)
.env             real settings, gitignored, never commit
.env.example     template for .env, committed
README.md
Running locally
IB Gateway must be running and logged in to the paper account
Backend: cd backend && source venv/bin/activate && uvicorn main:app --reload (port 8000)
Frontend: cd frontend && npm run dev (port 5173)
Mac app: cd frontend && npm run tauri dev (uses your own backend on 8000) or npm run build:app (PyInstaller backend bundled as a resource via src-tauri/tauri.release.conf.json; Rust starts it with PORTFOLIO_DATA_DIR = Application Support, keeps its stdin open so it exits with the app, SIGTERM on quit). Handshake: Rust picks a free port and a random per-launch token, passes the token as the first stdin line (--token-stdin), and injects window.__PORTFOLIO_BACKEND__ = {url, token} into the window (created in lib.rs, not tauri.conf.json); api.js sends X-App-Token on every request and the backend's require_app_token middleware returns 401 without it (dev has no token). The frontend shows 'Starting…' for up to 30 s, then 'not running'. Nothing secret is ever stored: no Keychain. The Anthropic key is entered in Settings (commands api_key_status / set_api_key / clear_api_key, frontend/src/appApiKey.js), sent to the backend over stdin and kept only in its memory until the app quits; IBKR credentials are never stored (the password goes to Gateway once; the username is in settings.json to pre-fill the form). Earlier builds' Keychain items are deleted once, without reading them, with /usr/bin/security (remove_old_keychain_items, flag keychain_removed). In development the key still comes from .env (config.anthropic_api_key()). Settings page (frontend/src/pages/Settings.jsx, sidebar App > Settings): API key (Keychain), Gateway port and appearance; works while disconnected. Non-secret settings live in settings.json in Application Support (src-tauri/src/settings.rs, commands get_settings / save_settings, frontend/src/appSettings.js) and reach the backend as {"set_setting": "ib_port"} over stdin; keep_connected reads config.ib_port() each attempt and reconnects when it changes. The backend API stays GET-only. Gateway setup (src-tauri/src/gateway.rs, commands gateway_status / install_gateway, frontend/src/appGateway.js, row in Settings): finds the newest complete 'IB Gateway 10.x' in ~/Applications or /Applications; downloads IBKR's stable-standalone macOS arm DMG to the app cache (resumes partial downloads), mounts it hidden and read-only, requires TeamIdentifier L6H6D9Q7DY (Interactive Brokers LLC) and spctl acceptance (notarised), then opens IBKR's installer for the user to click through. API settings are applied by IBC at launch from ibc_config() (port, ReadOnlyApi=yes, own settings dir), never by editing Gateway's files.
Sign-in (src-tauri/src/session.rs, commands login_state / saved_login / sign_in / reconnect / cancel_sign_in / sign_out, frontend/src/appSession.js + useLogin.js + pages/Setup.jsx): IBC 3.24.2 (repo archived 1 Sep 2026; fetched and SHA-256 checked by src-tauri/ibc/build-ibc.sh, never committed) runs Gateway with Gateway's bundled Java, launched directly (IBC's start script renames Gateway's app). Our StdinLauncher (src-tauri/ibc/launcher) reads the username and password from stdin; they are never in files or process arguments. Gateway settings live in Application Support/gateway/<paper|live>, away from ~/Jts. States come from IBC's stdout and Gateway's launcher.log; a failed login stops Gateway and is never retried (IBC's cold restart would retry the same password). After Gateway's daily restart (AutoRestartTime 11:45 PM) the app relaunches it with -Drestart=<folder holding the autorestart file> (no password needed); if IBKR wants a full sign-in instead, the session ends with sign_in_again. Reconnect automatically only covers Gateway's daily restart (relaunched without a password); at launch and after the weekly re-login the user signs in. The 2FA (IBKR Mobile approval) path is built but untested: only paper logins have been tried.
Packaging (#43): npm run build:dmg -> src-tauri/target/release/bundle/dmg/Portfolio Manager_0.1.0_aarch64.dmg (~47 MB, arm64). bundle.macOS.signingIdentity "-" makes Tauri ad-hoc sign the whole bundle (without it the seal is broken and a downloaded copy shows "damaged" instead of Open Anyway); build:backend re-signs PyInstaller's Python.framework library ad-hoc first. Check with codesign --verify --deep --strict and, on a quarantined copy (xattr com.apple.quarantine), spctl/syspolicy_check: expected findings are only "Adhoc Signed App" and "Notary Ticket Missing" until #44 (Developer ID + notarisation). No auto-updater.
Updates (#48): tauri-plugin-updater, checked from Rust (src-tauri/src/updater.rs) at launch (3 s after the first non-startup screen, quiet on failure) and from the app menu's Check for Updates… (emits check-for-updates to the page); UpdatePrompt.jsx shows it. Update Now order: download (signature checked) -> shutdown_for_update (Gateway, then backend: they run from inside the bundle) -> install -> app.restart(); an install error shows the release page link and Restart. Endpoint releases/latest/download/latest.json (public repo; drafts invisible). Version: only frontend/package.json (tauri.conf.json reads ../package.json; Cargo.toml's version is unused). Updater artifacts only in CI (src-tauri/tauri.updater.conf.json, needs TAURI_SIGNING_PRIVATE_KEY[_PASSWORD]); plugins.updater.pubkey in tauri.conf.json must be the real public key (the build rejects the placeholder when signing). Release = annotated tag vX.Y.Z -> .github/workflows/release.yml -> draft release; the user publishes it.
App icon: frontend/src-tauri/icon-source.png (1024, macOS proportions) is the only icon; regenerate with `npx tauri icon src-tauri/icon-source.png` from frontend/ (then delete the android/ios/Square* extras). The setup screens and favicon use copies (src/assets/app-icon.png, public/favicon.png).
Window: the app hides its title bar (TitleBarStyle::Overlay); the traffic lights are moved to x 20, y 22 by src-tauri/src/traffic_lights.rs (re-applied on resize), not Tauri's traffic_light_position, which wraps the web view and stopped the page loading; setup screens resize the window to the Figma frame sizes (appWindow.js); .in-app CSS leaves room for the traffic lights; drag regions are .drag-strip, the toolbar and .sidebar-drag.
Ports and client IDs: the app's Gateway uses port 4012 by default (settings version 2 moved a saved 4002 to 4012 once) and the app's backend client ID 17; development stays on IB_PORT 4002 and IB_CLIENT_ID 1, so both can run at once. Gateway allows one connection per client ID (error 326): ib_connection.py moves to the next ID on a clash and /health reports problem (client_id_in_use, refused, timeout, other), problem_for_s and port; the app explains the problem after 20 s of Connecting.
AI model: config.ai_model() (Settings model picker in the app, AI_MODEL in .env in development; only config.AI_MODELS are accepted). Default stays claude-haiku-4-5. Rust is in ~/.cargo/bin (rustup didn't edit the shell profile), so prefix PATH="$HOME/.cargo/bin:$PATH".

Backend rules
Connect to IB Gateway via a background task started in the FastAPI lifespan (keep_connected in main.py), using await ib.connectAsync(...); it retries every 5s so the server starts without Gateway and reconnects after drops. IB endpoints use Depends(require_ib) and return 503 while disconnected. Never use ib.connect() inside the server (it conflicts with uvicorn's event loop).
Any endpoint that touches ib must be async def, and should use the async versions of ib_async methods where they exist (e.g. accountSummaryAsync).
Connection is read only unless TRADING_MODE (.env, dev only) is paper or live; the Mac app is always off and its Gateway has ReadOnlyApi=yes. backend/trading.py status() is the single guardrail check (mode, account kind from managedAccounts: D... = paper, read-only connection, LIVE_TRADING_CONFIRM for live); every order endpoint must call it. Markets page (frontend/src/pages/Markets.jsx, Figma M6 / 1 Markets): GET /search (reqMatchingSymbolsAsync, STK on ASX/US primary exchanges, max 10, one search a second, cached 10 min) and GET /prices (build_quote, shared with /quotes, for any con_id; falls back to IB daily bars, which count against the history limit). Selecting a stock reuses HoldingDetail; not_owned stocks show the "You don't own" card and no AI summary. Recently viewed in localStorage "recentStocks". List panes share useResizableWidth. Order ticket (frontend/src/components/OrderTicket.jsx, Figma M6 / 2): opened by Buy/Sell in HoldingDetail's header (and the not-owned card), only enabled while trading.can_trade; previews as you type (POST /orders/preview, 500 ms pause); Review Order passes the preview (with its token) to onReview. Sheet styles: .sheet-backdrop/.sheet/.form-row/.pill-button. GET /trading/status feeds the toolbar account badge (Figma M6 "Account Badge"). POST /orders/preview (OrderRequest: con_id, action BUY/SELL, quantity, order_type MKT/LMT, limit_price) runs checked_order() -> trading.check_order (whole shares, limit price, value in base currency <= MAX_ORDER_VALUE, no selling more than held, trading status) then whatIfOrderAsync (10 s timeout); POST /orders/* shares the summaries' CORS and Origin rules. A preview that can submit returns a confirmation token (trading.ConfirmationTokens: memory only, single use, 120 s, bound to con_id/action/quantity/type/limit); POST /orders redeems it, re-runs checked_order, then ib.placeOrder (day order, RTH only), one at a time; trade_summary() is the order shape. POST /orders/{id}/cancel (no token; refused on a read-only connection) and /orders/{id}/modify (quantity/limit only, needs a preview token for the new numbers, re-runs checked_order, re-sends with the same order id). GET /orders/stream (SSE: orders snapshot from ib.trades(), then order on orderStatusEvent/execDetailsEvent via per-stream queues, heartbeat comment every 15 s); the frontend must read it with fetch (EventSource can't send X-App-Token). Never test against a live account.
Connection settings (IB_HOST, IB_PORT, IB_CLIENT_ID) come from .env via python-dotenv.
CORS allows http://localhost:5173, http://127.0.0.1:5173 and tauri://localhost (the Mac app window). GET only, except POST /summary/{con_id} and POST /portfolio-summary (generating an AI summary), which PathCORS in main.py allows from those origins only; the endpoint also checks the Origin header, since simple cross-site POSTs skip the preflight.
After installing any Python package, run pip freeze > requirements.txt from backend/ with the venv active.
Purchase dates (Milestone 5.1): IBKR Flex Web Service. config.flex_token() (secret: IB_FLEX_TOKEN in .env, memory only in the app via set_secret flex_token) and config.flex_query_id() (IB_FLEX_QUERY_ID / set_setting flex_query_id). mask_secrets also masks the Flex token by value. User setup guide: docs/flex-query.md (Activity Flex Query with Open Positions at Lot level + Trades, XML, last 365 days). The app's Settings rows for these need a Figma design first.
backend/flex_report.py downloads the report (SendRequest, then polls GetStatement while code 1019 'in progress', 20 x 3 s, 30 s timeouts; IBKR error codes become plain messages, never containing the token) and parse_report() returns stock lots (OpenPosition levelOfDetail LOT: con_id, quantity, cost_price, opened) and trades (Trade executions only; sells negative). Backend tests: cd backend && venv/bin/python -m unittest discover tests.
backend/lots.py: lots.sqlite (flex_lots, flex_trades, meta), refreshed by a lifespan task (keep_refreshed: checks every 3 h, fetches when the last success is a day old, retries a failure after an hour, records masked errors). lots_for(con_id, held) uses IBKR's Lot rows, else FIFO over the year's trades; extra dated shares come off the oldest lot, missing ones are unknown_quantity. CGT discount date = day after the first anniversary (ATO excludes the purchase day). GET /lots/status, GET /lots/{con_id} (needs IB for the quantity held).
AI portfolio summary (Milestone 5.2): spec in docs/portfolio-summary-spec.md (8 fixed sections, fact ids D:* plus H:<con_id> per holding, no news in v1, same ground rules and API shape as the stock summary).
Current API
GET /health returns {"connected": bool}
GET /positions returns a list of {"con_id", "symbol", "name", "name_truncated", "sec_type", "currency", "exchange", "quantity", "avg_cost", "market_price", "market_value", "unrealized_pnl", "unrealized_pnl_pct"} (from ib.portfolio(); names from contract details, cached, title-cased by backend/names.py; IB cuts longName at 28 characters, which sets name_truncated)
GET /account returns net_liquidation, cash, positions_value, buying_power, currency, unrealized_pnl, fx_rates ({currency: rate to base})
GET /quotes returns a list of {"con_id", "last", "prev_close", "day_change", "day_change_pct", "source"}. Tries delayed quotes (reqMarketDataType(3)); if IB sends none, source is "history" and day change comes from daily bars. Quote requests are skipped for 10 min after an empty answer.
GET /history/{con_id}?range=1D|1W|1M|3M|1Y|All returns {"con_id", "range", "bars": [{"time", "close"}]} via reqHistoricalDataAsync, cached 60s
GET /quotes also returns open, day_high, day_low, bid, ask, volume, avg_volume (volume and the 3-month average both from IB daily bars, so they match; IB volume runs below Yahoo's consolidated volume)
GET /profile/{con_id} (About; cached 1h), /stats/{con_id} (slow key statistics; cached 1h, shares one Ticker.info call with /profile), /news/{con_id} (cached 15 min), /performance/{con_id} (cached 1 day). Yahoo failures return 502 so only that section shows "unavailable"; unmapped exchanges return 404.
Yahoo rules (backend/yahoo.py): yahoo_symbol(contract) is the only IB -> Yahoo mapping (ASX -> .AX). yfinance is blocking, so calls run via asyncio.to_thread, one at a time (its SQLite cache errors with "database is locked" under parallel use). Caching via cached() in backend/cache.py (per-key lock, failures remembered 60s). News uses yf.Search by company name (Ticker.news returns 404); headlines must name the company; a bare ASX ticker counts only if the US company with that ticker is the same company. Benchmarks are total return indexes: ^AXJT and ^SP500TR.
AI summary (backend/summary_facts.py, ai_summary.py, summary_store.py):
  Portfolio summary (Milestone 5.2, docs/portfolio-summary-spec.md): backend/portfolio_facts.py builds D:portfolio, D:allocation, D:pnl, D:market_moves, D:concentration (20/40/80% flags), D:events (60 days), D:income, D:missing and H:<con_id> per holding, all in base currency; GET /portfolio-summary/facts previews it (STK holdings only). backend/portfolio_summary.py has the 8-section prompt, schema and extra advice checks (rebalance, trim, diversify) and reuses ai_summary.stream_sections/validate_section through keyword arguments; GET /portfolio-summary (latest + ai_configured), POST /portfolio-summary (SSE, same Origin/CORS rules, one at a time), saved in summaries.sqlite table portfolio_summaries (last 20). D:since_last compares with the last saved portfolio facts (money parsed back from the saved strings; holdings added/sold; weight changes of 1 point or more); GET /portfolio-summary/history and /history/{id}. Tests use a fake Claude client (no API calls).
  GET /summary/{con_id} returns the last saved summary and ai_configured; POST /summary/{con_id} streams Server-Sent Events (status, facts, section, done, error); GET /summary/{con_id}/facts previews the facts sheet (no API call).
  History: GET /summary/{con_id}/history (id, created_at, model, price; newest first), GET /summary/{con_id}/history/{summary_id} (one in full, same shape as latest), GET /summary/{con_id}/compare?a=&b= (older, newer, data_changes from compare_data in summary_facts.py). summary_store keeps the last 20 per stock (KEEP_PER_STOCK), pruned on save.
  Compare tags (frontend/src/summaryDiff.js) match points by wording, so they are a guide only; data_changes are exact. Moves under 1% of the old value are not tagged "Changed" and are marked minor in the data strip (MINOR_CHANGE_PCT in both files).
  All numbers are calculated in summary_facts.py; the model only explains them. Every facts block has an id (D:..., news N1...) and the response schema limits citations to those ids; unknown ids are removed and uncited points flagged anyway.
  10 fixed sections via structured outputs (output_config.format json_schema); sections are streamed as soon as each completes (jiter partial parsing). Summaries are saved in data/summaries.sqlite (gitignored); section 10 compares with the previous one.
  Section 10 (since_last_move in summary_facts.py): stock vs price index (^AXJO / ^GSPC) over exactly the window between summaries, using the index level saved with the previous summary (benchmark_level), else Yahoo 5-minute bars (about a month, cached 5 min), else daily closes. expected = beta x benchmark, residual = stock - expected, typical = 60-day daily volatility x sqrt(trading days, fractional); company specific if |residual| > 1.5 x typical; small_move if |stock| < typical; 1 percentage point rule only when beta or volatility is missing. Only news published between the summaries is offered; automatic checks flag causal wording, news cited for in-line moves and news outside the window.
  Purchase dates come from the Flex report when set up: summary_facts.position_lots() puts each lot (purchase date, CGT discount date, days until, whether it applies now) into D:position.lots, fills purchase_date / cgt_12_month_date with plain summaries for the card, and says when dates are unknown. Peers and sector performance are not available.
IB limits: about 60 history requests per 10 minutes, so history is cached. Error 10197 ("competing live session") means the live account is logged in elsewhere (TWS, mobile, web), which blocks market data on the paper account; history still works.
