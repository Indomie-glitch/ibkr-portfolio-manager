IBKR Portfolio Manager

A cleaner, more intuitive portfolio dashboard for Interactive Brokers, with AI generated stock summaries, trading, watchlists, and a Mac app. Personal learning project and portfolio piece, built to look professional on GitHub.

Stack
- Broker: IB Gateway running locally. Development uses the paper account on port 4002; the Mac app runs its own Gateway (port 4012 by default). Trading works on paper or live accounts.
- Backend: Python 3.11, FastAPI, uvicorn, ib_async (the maintained fork of ib_insync; do not use ib_insync), yfinance for data IB doesn't provide.
- Frontend: React with Vite, in frontend/. Plain CSS, no Tailwind, no chart library (charts are hand-drawn SVG).
- Mac app: Tauri 2 (Rust) in frontend/src-tauri/, with the backend bundled by PyInstaller.
- AI: Claude API. The model is config.ai_model(): AI_MODEL in .env in development, the Settings model picker in the app; only config.AI_MODELS are accepted; default claude-haiku-4-5. A model added to config.AI_MODELS also needs a price in backend/usage_store.PRICES.

Running locally
- IB Gateway must be running and logged in to the paper account.
- Backend: cd backend && source venv/bin/activate && uvicorn main:app --reload (port 8000). --reload serves whatever branch is checked out.
- Frontend: cd frontend && npm run dev (port 5173).
- Mac app: cd frontend && npm run tauri dev (uses your own backend on 8000), or npm run build:app / npm run build:dmg (bundled backend).
- Rust is in ~/.cargo/bin (rustup didn't edit the shell profile), so prefix PATH="$HOME/.cargo/bin:$PATH".
- Tests: backend: cd backend && venv/bin/python -m unittest discover tests. Frontend: cd frontend && npm test (Vitest; *.test.js next to the code in src/lib), npm run lint, npm run build. Tests that use Claude use a fake client (no API calls); tests must point every SQLite store (summary_store, news_sentiment, usage_store, lots, risk_data, constituents, directors, supply_chain: a temp path to db.open_graph) at a temp file.

Backend rules
- Connect to IB Gateway from the keep_connected background task started in the FastAPI lifespan (ib_core.py), with await ib.connectAsync(..., readonly=False); it retries every 5 s, so the server starts without Gateway and reconnects after drops. Never use ib.connect() inside the server (it conflicts with uvicorn's event loop). IB endpoints use Depends(require_ib) and return 503 while disconnected.
- Any endpoint that touches ib must be async def and use the async ib_async methods where they exist (e.g. accountSummaryAsync).
- Connection settings: IB_HOST, IB_PORT, IB_CLIENT_ID from .env in development; in the app the port comes from Settings (config.ib_port(), read on every connect attempt). Gateway allows one connection per client ID (error 326): ib_connection.py moves to the next ID on a clash. The app's backend starts at client ID 17 and development at 1, so both can run at once. GET /health returns {"connected": true}, or when disconnected {"connected": false, "port", "problem" (client_id_in_use, refused, timeout, other), "problem_for_s"}; the Mac app explains the problem after 20 s of connecting (ConnectionMessage.jsx). Connected but not answering (#285): IBKR allows one session per username, so a login elsewhere (mobile, Client Portal, TWS, another Gateway) cuts Gateway off while its port stays open; keep_connected runs ib_core.check_answering every 20 s (positions + open orders, 10 s limit; 2 misses in a row) and IB errors 1100 / 2110 (lost) and 1101 / 1102 (restored) count too; /health then adds "problem": "not_answering", "port", "problem_for_s" with connected true. The frontend (connectionState not_answering) stops loading and shows "Your IBKR session may have been taken over…" with Sign in again in the app (signs out, then the sign-in form).
- Requests are GET, except these POSTs: POST /summary/{con_id}, POST /portfolio-summary (generate AI summaries) and POST /orders, /orders/preview, /orders/{id}/cancel, /orders/{id}/modify, /trading/borrowing (development only). CORS (PathCORS in main.py) allows http://localhost:5173, http://127.0.0.1:5173 and tauri://localhost, with POST only on those paths; every POST also calls web.check_origin, since simple cross-site POSTs skip the preflight.
- Secrets: never print or log a key or token. Errors are logged through secrets_guard.mask_secrets, which masks anything shaped like an Anthropic key, and the Flex token by its value.
- IB limits: about 60 history requests per 10 minutes, so history is cached. Error 10197 ("competing live session") means the live account is logged in elsewhere (TWS, mobile, web), which blocks market data on the paper account; history still works.
- Never test against a live account.

Mac app
- Startup handshake: Rust (lib.rs) picks a free port and a random per-launch token, starts the bundled backend with PORTFOLIO_DATA_DIR = Application Support, passes the token as the first stdin line (--token-stdin) and keeps stdin open so the backend exits with the app (SIGTERM on quit). It injects window.__PORTFOLIO_BACKEND__ = {url, token} into the window (created in lib.rs, not tauri.conf.json). api.js sends X-App-Token on every request; the backend's require_app_token middleware returns 401 without it (development has no token). The frontend shows "Starting…" for up to 30 s, then "Not running".
- Secrets: the IBKR password is never stored (it goes to Gateway once; the username is saved in settings.json to pre-fill the form). The Anthropic key is entered in Settings (commands api_key_status / set_api_key / remember_api_key / clear_api_key, desktop/appApiKey.js), sent to the backend over stdin ({"set_secret": "anthropic_api_key"}) and kept in its memory (and Rust's, for the toggle) until the app quits. Only with "Remember key on this Mac" (#277, off by default) is it also saved by src-tauri/src/keystore.rs: ChaCha20-Poly1305, api_key.enc in Application Support, with a random 32 byte per-install key in api_key.secret; both mode 600, no Keychain. At launch restore_api_key decrypts it and sends it over stdin as above; the backend never reads the files; an undecryptable file is deleted and the key asked for again. Remove and turning the toggle off delete both files. Accepted trade-off: the encryption key is on the same Mac (README recommends a monthly spend limit on the key). In development the key comes from .env. Earlier builds' Keychain items are deleted once, without reading them, with /usr/bin/security (remove_old_keychain_items, flag keychain_removed).

Data and API reference
- GET /positions: list of {con_id, symbol, name, name_truncated, sec_type, currency, exchange, quantity, avg_cost, market_price, market_value, unrealized_pnl, unrealized_pnl_pct} from ib.portfolio(); names from contract details, cached, title-cased by names.py; IB cuts longName at 28 characters, which sets name_truncated.
- GET /account: net_liquidation, cash, positions_value, buying_power, currency, unrealized_pnl, fx_rates ({currency: rate to base}).
- GET /quotes: per holding {con_id, last, prev_close, day_change, day_change_pct, source, open, day_high, day_low, bid, ask, volume, avg_volume}. Tries delayed quotes (reqMarketDataType(3)); if IB sends none, source is "history" and the day change comes from daily bars; quote requests are skipped for 10 min after an empty answer. Volume and its 3-month average both come from IB daily bars (IB volume runs below Yahoo's consolidated volume).
- GET /history/{con_id}?range=1D|1W|1M|3M|1Y|All: {con_id, range, bars: [{time, close}]} via reqHistoricalDataAsync, cached 60 s.
- Yahoo (yahoo.py): GET /profile/{con_id} (About, cached 1 h), /stats/{con_id} (cached 1 h, shares one Ticker.info call with /profile), /news/{con_id} (cached 15 min), /performance/{con_id} (cached 1 day), /executives/{con_id} (#112, cached 1 week: Ticker.info companyOfficers through yahoo.executives_from_info: executives, each with is_director when the title also has a board seat ("CEO & Director"), and board-only members under directors for #113; classify_title: a board seat is "director" not followed by "of" or "chair…", management = chief / VP / officer / secretary / head of …, "Non-Executive" doesn't count, no title = officer; clean_person_name drops honorifics and degrees; age / year_born / pay (pay_currency = financialCurrency, pay_fiscal_year) when listed; year_started, wikidata_id and wikipedia_url are always null because Yahoo has none, for #113 / #114 to fill by matching). Yahoo failures return 502 so only that section shows "unavailable"; unmapped exchanges return 404. yahoo_symbol(contract) is the only IB -> Yahoo mapping (ASX -> .AX). yfinance is blocking, so calls run via asyncio.to_thread, one at a time (its SQLite cache errors with "database is locked" under parallel use). Caching via cached() in cache.py (per-key lock, failures remembered 60 s). News uses yf.Search by company name (Ticker.news returns 404); headlines must name the company; a bare ASX ticker counts only if the US company with that ticker is the same company. Performance benchmarks are total return indexes: ^AXJT and ^SP500TR.
- News sentiment (#170, news_sentiment.py): /news/{con_id} items carry sentiment {direction positive/negative/neutral, strength 1-3 (null for neutral), reason}, or null (no key, or the call failed; retried after 5 min). New headlines for a stock go to config.ai_model() in one structured-output call; answers are saved per (con_id, url) in news_sentiment.sqlite (90 days). Arrows (#97): components/detail/SentimentArrows.jsx (Figma 70:514; drawn with currentColor = --gain/--loss; the reason is the hover title), before the chevron in NewsSection.
- Index members (#109, #110, constituents.py, routers/indices.py): S&P 500 (State Street SPY .xlsx), Nasdaq 100 (iShares UK CNDX CSV), Dow (State Street DIA), ASX 20 (iShares ILC), ASX 50 (State Street SFY), ASX 200 (State Street STW): ETF daily holdings files (no key; full replication, so members match; weights rescaled to 100% without cash/futures; .xlsx read by pandas + openpyxl). Tickers in IB's form ("BRK B"; clean_symbol). indices.sqlite: members (per index and market), indexes (as_of = the file's date, fetched_at, last_error), companies (per market + symbol: name, market cap, trailing P/E and 52-week price change (return_1y, %) from Yahoo's screener daily (yahoo.fetch_market_stats: pages of 250 by market cap, ASX up to 2, US exchanges without OTC up to 8, stopping once every member is seen; market_cap_at dates all three; new columns added to #109 stores on open), Yahoo profile sector + industry, filled one at a time in the background, PROFILE_PAUSE_S, stops after 3 failures; until then the fund's GICS sector: classification). keep_refreshed (lifespan) runs while config.index_loader_enabled() (on by default since #114; off with INDEX_LOADER=0 in .env, or "load_index_members": false in settings.json -> {"set_setting": "index_loader"}; settings version 3 switched it on once for apps that had saved it off; checked every minute so it can change while running). Once on, it first loads seed/indices.json when there's no indices.sqlite yet (bundled by portfolio-backend.spec; rebuild with `python constituents.py --seed` from backend/, which refuses to write an incomplete seed; tests check it covers every index and member), then checks every 3 h, refetches an index after 7 days, retries a failure after 6 h; a failed or short download (min_count) keeps the last copy and marks it stale. GET /indices (status), GET /indices/{con_id} (indexes a stock is in: weight %, rank by weight, count, as_of, stale), GET /indices/{index_id}/members. No UI yet.
- Competitors (#111, competitors.py pure, route GET /competitors/{con_id} in routers/indices.py): the stock's Yahoo industry among looked-up index companies of both markets (constituents.universe()); fewer than MIN_PEERS (4) widens to related industries (family_of: text before " - ", plus our FAMILIES map), then the sector; answer has level (industry / related / sector), label, industries, peers_total. Ranked by market cap in USD (fx.rate_to_base AUD; 502 without it); companies = top LIMIT (20) plus the stock itself (is_self) and any you own (owned, owned_con_id from ib.portfolio()), each with rank, market, currency, market_cap (own currency), market_cap_usd, return_1y, pe. For #114 / #279: peers have no con_id (only owned ones).

Wikidata: the people Wikidata links to the company (board member P3320, CEO P169, chair P488; company by CIK P5531 or ASX ticker), matched by name within that list only (people.wikidata_match: one match or none; short forms like Sue/Susan). Links across companies (people.link_basis): same Wikidata ID, or same match_key (first + last, no titles, degrees, honours, middle names or apostrophes) AND one document names the other company in other_boards ("named_in_document"); same name alone is a possible_match, never a link. Company names for that come from Yahoo's longName (IB cuts at 28 characters). Seed: `python directors.py --seed` (from backend/; US index members; merged at startup by merge_seed: new companies and newer documents; skips a seed already merged; never ASX). keep_checked (lifespan): every 6 h, each read company at most weekly, no AI, marks a newer document. GET /directors/{con_id} (stored board or status not_read with needs: api_key / sec_contact_email / asx_terms / unsupported_market), POST /directors/{con_id} (reads now; 409 with what's missing, 502 when a source fails, which keeps the stored board), GET /people/{person_id}. Usage feature "directors". No UI yet (#114).
- Supply chain graph (Milestone 10, #115; backend/supply_chain/, docs/supply-chain-graph.md has the ER diagram and conventions): supply_chain.sqlite in DATA_DIR, opened with db.open_graph() (foreign keys on, autocommit, db.transaction() for atomic writes, numbered migrations in migrations.py each with a checksum: never edit a shipped one, add a new one; SchemaError for a newer or edited database). Tables: companies (placeholders for unnamed "Customer A"), identifiers (scheme, market, value unique), documents (unique per source + external id, content_hash, status), relationships, evidence, rejected, jobs (one open job per kind + key, higher priority first), runs (cost_usd per attempt), themes, theme_companies. Direction: supplier sells to customer. supplier_revenue_share = % of the supplier's revenue from this customer; customer_supply_share (+ customer_share_scope) = % of what the customer buys from this supplier ("TSMC makes all of Apple's chips" = 100, scope "chips"); both nullable, 0-100. Every relationship points to its evidence IN THE DATABASE: relationships.primary_evidence_id is NOT NULL and a deferred composite foreign key to evidence (relationship_id, id), so graph.add_relationship writes both rows in one transaction and the commit fails otherwise; evidence needs a document and a quote; the primary evidence can't be deleted; integrity.check() finds outside damage. Relationships are never deleted (status ended / stale). Evidence tiers 1 structured (XBRL, supplier lists), 2 AI-read and verified, 3 news. Portable SQL (Postgres in Milestone 13, #148). Job queue (#116, supply_chain/jobs.py + worker.py): jobs.enqueue(kind, key, payload, priority) (one open job per kind + key; asking again keeps the higher priority), claim (atomic BEGIN IMMEDIATE; priority desc, then run_after, then id; only kinds the worker has a handler for; starts a runs row), finish (cost on the run), fail (retry with back-off 30 s x4 per attempt up to 6 h + up to 20% jitter, dead when attempts reach max_attempts (3), failed for a permanent error), release (orderly stop: the attempt isn't counted), recover (jobs running with a stale lock: timedelta(0) at the start of the only runner; the interrupted attempt counts, so a poison job dies), requeue, cancel, counts, spent_since (daily budget). worker.Worker.run_once / run_forever with @worker.handler(kind) functions `async def (job, conn)` returning None or {notes, model, input_tokens, output_tokens, cost_usd}; raise worker.Permanent for no retry; 15 min handler timeout; heartbeat every minute; keep_running() is a lifespan task that waits for config.pipeline_enabled() (PIPELINE=1, off by default: it downloads filings and spends AI budget) with config.pipeline_workers() (PIPELINE_WORKERS, default 2) workers. SEC client (#117): backend/sec_client.py is the only EDGAR client (the boards job's directors_sources wraps it): User-Agent from config.sec_contact_email, ~6 requests a second, retries on 429/5xx/dropped connections honouring Retry-After (SecUnavailable; SecNotFound for 404), cik_for_ticker, submissions (cached 1 h), list_filings(cik, forms, since, until) (reads older pages only when `since` reaches back), filing_files (index.json), download (data/filings/<cik>/<accession>/, SHA-256, atomic write). supply_chain/sec.py registers a filing as a document (source sec, status discovered) and fetch_document downloads it (status downloaded, content_hash). Nothing is queued by the app yet (#118 scout is next).
- Usage and cost (#86, usage_store.py): usage.sqlite table ai_usage, one row per Claude call (feature stock_summary / portfolio_summary / news_sentiment / directors, model, tokens, cost_usd priced at call time from PRICES, outcome; refused or cut-off answers are logged too, via SummaryError.usage).
